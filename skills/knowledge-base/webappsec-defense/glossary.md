# Glossary

**ABAC (Attribute-Based Access Control)** — authorization model checking subject/object/policy attributes rather than fixed roles (Ch10)
**Advanced Persistent Threat (APT)** — sophisticated, usually state-sponsored hacking group tracked by signature techniques, e.g. Cozy Bear, Charming Kitten (Ch1)
**Allow list** — validating input against what's explicitly permitted, preferred over block lists (Ch4, Ch12, Ch25, Ch46)
**Anti-CSRF token** — server-issued, unpredictable value bound to a session/form that must accompany state-changing requests (Ch6, Ch26, Ch44)
**ARP spoofing** — forging Address Resolution Protocol replies to position an attacker as a MITM on a local network (Ch7)
**Archetypal vulnerability** — a generic, well-known exploitable pattern (XSS, SQLi) vs. an app-specific business logic flaw (Ch25, Ch40)
**Attack surface** — the total set of points where an attacker could interact with or attempt to compromise a system (throughout)
**Big-game hunting** — attackers targeting large organizations because compromise is more lucrative (Ch1)
**Billion laughs attack** — an XML entity-expansion DoS using nested entity references (Ch11)
**Blind injection** — an injection attack where the attacker infers success via timing or behavior rather than direct output (Ch28)
**Block list** — validating input against what's explicitly forbidden; weaker than an allow list since it can't anticipate novel bypasses (Ch4, Ch25, Ch40)
**Blocklist anti-pattern** — a named code-review anti-pattern: relying on denylists instead of allowlists (Ch40)
**Boilerplate code anti-pattern** — copy-pasted security code applied without understanding its context, creating false confidence (Ch40)
**Botnet** — a network of compromised machines controlled for cryptomining, spam, click fraud, or resale (Ch1)
**Business logic vulnerability** — an app-specific flaw in how legitimate features can be chained or abused (not a generic pattern) (Ch33, Ch51)
**Certificate Authority (CA)** — trusted entity that issues and vouches for TLS certificates (Ch3, Ch7)
**Certificate transparency** — public logs of issued TLS certificates, monitored to detect fraudulent issuance (Ch7)
**Clickjacking** — tricking a user into clicking a disguised, often invisible, overlaid UI element (Ch6, Ch16, Ch31, Ch34, Ch49)
**Client/Server Separation violation** — a named anti-pattern: security logic duplicated or drifted between client and server instead of enforced server-side (Ch40)
**Content Security Policy (CSP)** — an HTTP header restricting which script/style/resource sources a page may load or execute (Ch2, Ch6, Ch22, Ch28, Ch37, Ch43)
**Cookie attributes: Secure / HttpOnly / SameSite** — flags restricting cookies to HTTPS-only, JS-inaccessible, and cross-site-request behavior respectively (Ch2, Ch9, Ch22, Ch37)
**CORP (Cross-Origin-Resource-Policy)** — header limiting which origins may load a given resource, mitigating Spectre-class attacks (Ch22, Ch37)
**COOP (Cross-Origin-Opener-Policy)** — header isolating a page's browsing context from cross-origin openers, blocking tabnabbing-style attacks (Ch22, Ch34, Ch37, Ch49)
**CORS (Cross-Origin Resource Sharing)** — mechanism for relaxing the same-origin policy for specific origins/methods (Ch2, Ch22, Ch37)
**Credential stuffing** — retrying a stolen username/password database against one target site (Ch1, Ch8)
**CRLF injection** — injecting carriage-return/line-feed sequences to forge log entries or split HTTP responses (Ch12)
**CSRF (Cross-Site Request Forgery)** — tricking an authenticated user's browser into making an unwanted state-changing request (Ch6, Ch11, Ch26, Ch29, Ch44)
**CVE (Common Vulnerabilities and Exposures)** — MITRE's public database of disclosed, patched vulnerabilities (Ch1, Ch13, Ch21, Ch32, Ch35, Ch50)
**CVSS (Common Vulnerability Scoring System) v3.1** — standardized Base/Temporal/Environmental scoring framework for vulnerability severity (Ch27, Ch42)
**Dark pattern / Light pattern** — UI designs that manipulate users against their interest vs. author-coined "light patterns" that nudge users toward safer choices (Ch23, Ch38)
**Data Transfer Object (DTO)** — a pattern that explicitly defines which fields may cross a trust boundary, preventing mass assignment (Ch33, Ch48)
**Defense in depth** — layering independent, redundant protections so no single control failure is fatal (Ch4, Ch5, Ch35)
**DKIM (DomainKeys Identified Mail)** — email authentication signing outbound mail with a key published in DNS (Ch14)
**DMARC** — DNS policy record instructing receivers how to handle mail failing SPF/DKIM checks (Ch14)
**DNS poisoning** — corrupting DNS resolution to redirect victims to attacker-controlled hosts (Ch7)
**DNSSEC** — cryptographic signing of DNS records to prevent poisoning/spoofing (Ch7)
**Doppelganger domain / homograph attack** — visually similar or Punycode-encoded domains used to impersonate a legitimate site (Ch7)
**DOM-based XSS** — cross-site scripting where the vulnerable data flow (source→sink) exists entirely in client-side JavaScript, invisible to server-side/static analysis (Ch6, Ch10, Ch25)
**Downgrade attack** — forcing a connection to use a weaker protocol version (e.g., TLS→SSL) to enable further attacks like POODLE (Ch7)
**Dnscan** — an open-source subdomain dictionary-attack tool (Ch19)
**Drive-by vulnerability scanning** — automated, indiscriminate scanning of internet-facing hosts for known flaws (Ch1)
**Fetch Metadata headers (Sec-Fetch-*)** — browser-sent request-context headers usable for isolation policies (Ch34, Ch49)
**Four-eyes principle** — requiring one author plus one independent, judgment-exercising approver for sensitive changes (Ch5)
**Frame-ancestors** — a CSP directive restricting which origins may embed a page in a frame, the modern clickjacking defense (Ch6, Ch34, Ch49)
**GraphQL** — a query-language API paradigm covered as a modern alternative to REST, with its own recon/attack surface (Ch18)
**HMAC** — a keyed hash used to verify integrity/authenticity of data, e.g. signed serialized state (Ch11)
**HSTS (HTTP Strict Transport Security)** — header instructing browsers to always use HTTPS for a domain (Ch3, Ch7, Ch22, Ch37)
**IDOR (Insecure Direct Object Reference)** — accessing another user's resource by tampering with a predictable identifier (Ch15, Ch30, Ch48)
**Implicit vs. explicit trust** — Zero Trust's core distinction: never trusting based on network location or session age; always re-verifying (Ch21, Ch36)
**Injection (SQL/NoSQL/LDAP/command/code)** — attacker data interpreted as command/query syntax due to lack of parameterization (Ch12, Ch28, Ch31, Ch46)
**Least privilege / Least Authority** — granting only the minimum permissions a process, person, or dependency needs (Ch4, Ch5, Ch7, Ch21, Ch31, Ch36, Ch46)
**Living off the land** — attackers using pre-existing local tools to avoid introducing detectable malware (Ch1)
**Lockout attack** — abusing account-lockout policies to deny legitimate users service by intentionally triggering lockouts (Ch8)
**Malicious insider** — a rogue employee/contractor leaking data, mitigated by need-to-know access rather than code controls (Ch1)
**Mass assignment** — binding an entire request payload to an object/DB row without field allowlisting, letting attackers set unintended fields (Ch11, Ch15, Ch30, Ch33, Ch48)
**MFA (Multi-Factor Authentication)** — requiring a second independent proof of identity beyond password (Ch8, Ch21, Ch36)
**MITM (Monster/Man-in-the-Middle)** — an attacker intercepting traffic between two parties (Ch7)
**Mutation-based XSS (mXSS)** — XSS that bypasses sanitizers because the DOM's parsing/mutation behavior differs from the sanitizer's parsing context (Ch10, Ch25)
**NIST SP-800-207** — the Zero Trust Architecture standard (Ch21, Ch36)
**Open redirect** — an endpoint that redirects to an attacker-supplied URL, abused for phishing (Ch14)
**Parameterized/prepared statement** — a query mechanism separating code from data, the standard injection defense (Ch4, Ch12, Ch28, Ch31, Ch46)
**Path/directory traversal** — using `../` or similar sequences to escape an intended file directory (Ch11)
**Pepper** — a server-side secret added to passwords before hashing, stored separately from the salt/hash (Ch3, Ch8)
**Principle of Least Authority (PoLA)** — Hoffman's term for least privilege applied to code execution contexts (Ch31, Ch46)
**Priority Zero (P0) event** — an organization's highest-severity security incident classification (Ch1)
**Prototype Pollution** — polluting a JavaScript object's shared prototype chain (`__proto__`) to inject properties app-wide (Ch11, Ch18, Ch31, Ch34, Ch49)
**Quasi-cash attack** — abusing payment/rewards logic (e.g., self-invoicing + cashback) to launder value at near-zero cost (Ch33)
**RBAC (Role-Based Access Control)** — authorization model granting permissions via named roles (Ch10, Ch17)
**ReDoS (Regular Expression Denial of Service)** — a regex with catastrophic backtracking causing CPU exhaustion on crafted input (Ch12, Ch29, Ch47)
**Reflected XSS** — injected script echoed immediately from a request (e.g. a URL parameter) into the response (Ch6, Ch25)
**Salt** — a unique, random value combined with a password before hashing to defeat lookup-table/rainbow-table attacks (Ch3, Ch8)
**Same-origin policy** — the browser rule restricting scripts to interacting only with resources sharing protocol+domain+port (Ch2, Ch18, Ch22)
**SameSite (cookie attribute)** — restricts whether a cookie is sent with cross-site requests (Lax/Strict/None) (Ch6, Ch9, Ch22)
**SAML** — an XML-based single sign-on protocol using a service provider and assertion consumer service (ACS) (Ch8)
**Serialization/Deserialization attack** — exploiting unsafe reconstruction of objects from serialized data to achieve RCE or tampering (Ch11, Ch15, Ch30, Ch48)
**Session fixation** — forcing a victim to use an attacker-known session ID, then hijacking it post-authentication (Ch9)
**Session hijacking** — stealing a valid session identifier to impersonate an authenticated user (Ch9)
**Shadow Realms** — a TC39-proposed JS sandboxing mechanism for isolating untrusted code (Ch22, Ch37)
**SPF (Sender Policy Framework)** — DNS record listing servers authorized to send mail for a domain (Ch14)
**SQL injection** — inserting SQL syntax via unparameterized query construction to alter query logic (Ch4, Ch12, Ch28, Ch46)
**SRI (Subresource Integrity)** — a hash attribute on `<script>`/`<link>` tags verifying fetched resource content hasn't been tampered with (Ch2, Ch22, Ch37)
**SSRF (Server-Side Request Forgery)** — tricking a server into making requests to attacker-chosen internal/external destinations (Ch11, Ch14)
**Statistical modeling (business logic defense)** — using headless-browser-recorded legitimate-usage models to detect anomalous behavior (Ch33, Ch51)
**Sticky load balancing** — routing a client's requests to the same backend server, often used to support server-side sessions (Ch9)
**Tabnabbing / Reverse tabnabbing** — using `window.opener`/`window.parent` from a linked or opened page to redirect the origin tab to a phishing page (Ch16, Ch31, Ch34, Ch49)
**Threat modeling (five-goal framework)** — document knowledge → identify threat actors → identify risks/vectors → identify mitigations → identify delta (Ch24, Ch39)
**Timing attack** — inferring secret information (e.g., account existence) from response-time differences (Ch8)
**Trust-by-default anti-pattern** — code that trusts input, dependencies, or callers without verification (Ch40)
**Trust boundary** — the conceptual line separating trusted internal logic from untrusted external input (Ch10)
**User enumeration** — inferring valid usernames/accounts from differing error messages or timing (Ch8, Ch23, Ch38)
**Vertical/horizontal privilege escalation** — gaining higher-tier permissions (vertical) or another user's same-tier access (horizontal) (Ch10)
**WebAuthn** — a browser API standard for public-key-based authentication (including biometrics/hardware keys) (Ch8)
**XSS (Cross-Site Scripting): stored/reflected/DOM-based/mutation-based** — injecting attacker-controlled script into pages viewed by other users (Ch6, Ch10, Ch25, Ch28, Ch43)
**XXE (XML External Entity)** — abusing XML parsers' external entity resolution to read files or exfiltrate data (Ch11, Ch12, Ch27, Ch30, Ch45)
**Zero-day vulnerability** — a flaw just publicly disclosed, creating a race between patching and exploitation (Ch1)
**Zero Trust Architecture** — security model assuming no implicit trust from network location or session age; continuous re-verification (Ch21, Ch36, Ch52)
**Zone transfer attack** — abusing misconfigured DNS servers to dump an entire zone's subdomain records (Ch7, Ch19)
