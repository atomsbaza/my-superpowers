# Chapter 13: Refactoring, Reuse, and Reality

## Core Idea
This chapter (contributed by Will Tracz, etc.) discusses the practical realities of refactoring in real-world environments, dealing with management, legacy code, and the economics of software reuse.

## Key Concepts
- **The Reality of Refactoring**: Refactoring is hard to justify to non-technical management if pitched as "cleaning up." It must be pitched as a way to deliver features faster and with fewer bugs.
- **Refactoring and Performance**: Refactoring might slow down code slightly, but it makes the code easier to understand and thus easier to tune for performance later.

## Key Takeaways
1. Don't ask for permission to refactor. Just do it as part of your normal development process.
2. Write tests for legacy code before you refactor it.\n
