# Graph Engineering Knowledge Base — Glossary

**Access Control Pattern** — graph design pattern modeling RBAC/group permissions natively; traversal beats multi-join ACL tables (Topic 5)
**Adversarial Verification (N-Skeptics)** — submitting a finding to N independent, context-isolated skeptic agents who default to "false" under uncertainty; reported only on majority vote (Topic 13)
**Agentic GraphRAG** — an autonomous agent iteratively writing/executing graph queries and deciding whether to traverse further before synthesizing an answer; not present in the source corpus, described via outside knowledge (Topic 9)
**Barrier Abuse** — anti-pattern of using a synchronization barrier where an independent pipeline would suffice, creating a "staircase effect" latency penalty (Topic 12)
**Barrier Synchronization (Pregel)** — coordination pattern where execution proceeds in bounded "super-steps"; all active nodes finish and update state before the next step begins (Topic 1, Topic 7)
**Bitemporal Versioning** — modeling entities as immutable historical records using a `Status` property (not nullable end-dates) for deterministic merging and audit trails (Topic 5)
**Clique Explosion** — anti-pattern of fully connecting every node sharing a trait, producing O(degree²) edge complexity (Topic 2, Topic 5, Topic 10)
**Closed-World Assumption (CWA)** — SHACL's validation stance: anything not explicitly stated is considered false/invalid (Topic 3, Topic 4)
**Context Graph** — a temporary, bespoke subgraph assembled by traversing a knowledge graph to answer one specific query; the core GraphRAG retrieval mechanism (Topic 1, Topic 9)
**Conditional Edge Routing** — inspecting an agent's output via deterministic code to determine the downstream graph path at runtime (Topic 12)
**Convergence Loop / Loop-Until-Dry** — iterating discovery rounds until K consecutive rounds surface nothing new, deduping against everything seen (Topic 13)
**Degenerate Graph** — a linear, unbranching agent script (every node: one edge in, one edge out); fragile and unparallelizable (Topic 1, Topic 11)
**Diamond Pattern** — the fan-out/fan-in orchestration topology: split → work → merge (Topic 12)
**DB Hit** — the abstract unit of storage-engine work (reading a property, traversing a relationship) measured by `PROFILE`; minimizing DB Hits is the primary query-tuning goal (Topic 6)
**Edge (data engineering)** — a connection denoting a relationship between two entities (Topic 1, Topic 2)
**Edge (AI orchestration)** — a data contract defining the transition, dependency, and control flow between two nodes; exists only when data actually moves across it (Topic 11)
**Entity Flattening** — LLM extraction failure where a typed entity is recorded as a plain string literal, breaking relational mapping (Topic 3, Topic 4, Topic 9)
**Entity Resolution (ER)** — determining which fragmented data pieces relate to the same real-world entity, via graph algorithms like Node Similarity and WCC (Topic 4, Topic 8)
**Failure Isolation / Null-Tolerant Collection** — treating individual agent death as localized data loss, not run failure, by resolving to `null` and `.filter(Boolean)` on fan-in (Topic 12, Topic 13)
**Fan-Out / Fan-In** — deploying multiple independent agents concurrently, then merging their results (Topic 1, Topic 12)
**GraphCast** — Google DeepMind's encoder-processor-decoder GNN delivering 10-day weather forecasts in under a minute (Topic 10)
**GraphFrames** — DataFrame-based Apache Spark graph library, GraphX's modern successor, with native Python support and Motif finding (Topic 2, Topic 7)
**GraphRAG** — retrieval-augmented generation anchored in a knowledge graph via Context Graph traversal, instead of flat vector similarity search (Topic 1, Topic 9)
**GraphX** — RDD-based Apache Spark graph library using vertex-cut partitioning and a Triplet View; lacks first-class Python bindings (Topic 7)
**Graph Attention Networks (GAT)** — spatial GNN variant using learned attention weights to prioritize structural connections (Topic 10)
**GraphSAGE** — spatial GNN variant using neighborhood sampling (Topic 10)
**Graph Convolutional Network (GCN)** — spectral GNN variant using graph Laplacian averaging; e.g. Pinterest's PinSage (Topic 10)
**Graph Neural Network (GNN)** — ML architecture learning from interconnected data via message passing (Topic 1, Topic 10)
**Graph Thinking** — the unifying principle that computation itself is a graph; application state is a graph, agent logic is a traversal over it (Topic 14)
**Hierarchy Hallucination** — LLM failure of hallucinating the depth, logical accuracy, or relationships of a generated ontology structure (Topic 4)
**Holon** — a self-contained unit of extracted meaning (via RDF 1.2 reification) that is simultaneously a complete statement and a cooperating part of the global graph (Topic 1, Topic 3)
**Index-Free Adjacency** — native graph database architecture storing relationships as direct memory pointers, enabling constant-time traversal (Topic 1, Topic 2)
**Judge Panel** — N parallel generative attempts, scored by judge agents against a rubric, synthesized by grafting runners-up' best elements onto the winner (Topic 13)
**Knowledge Graph Engineering (KGE)** — the discipline ensuring semantic consistency of graph data via OWL/SKOS/SHACL (Topic 1, Topic 3)
**Knowledge Spine** — a central, unified taxonomic backbone in enterprise data architecture that domain-specific graphs branch off from; not present in the source corpus, described via outside knowledge (Topic 9)
**Labeled Property Graph** — the property graph model where nodes have identifiers/labels/properties and edges have identifiers/types/properties (Topic 2)
**Linear Path Projection** — chaining related nodes sequentially instead of fully connecting them, reducing edge complexity from O(degree²) to O(degree) (Topic 2, Topic 5, Topic 10)
**Mammoth Transaction** — a long-running read/write query spanning huge portions of the graph, starving concurrent short transactions (up to 4.7x throughput drop) (Topic 6)
**Message Passing** — the core GNN mechanism where nodes iteratively aggregate information from local neighbors (Topic 10)
**Model Tiering / Model Routing** — assigning cheap/fast models to wide mechanical nodes and premium models to narrow high-stakes synthesis/verification nodes (Topic 12, Topic 13)
**Motif Finding** — GraphFrames' declarative API for matching structural patterns (triangles, chains) via a domain-specific language (Topic 7)
**Multi-Agent Premium** — the documented ~15x token cost of a multi-agent system vs. 1x for a standard chat, due to context duplication/re-establishment across agent boundaries (Topic 12)
**Node (data engineering)** — a single data entity with an identifier, label, and properties (Topic 1, Topic 2)
**Node (AI orchestration)** — a bounded unit of work (deterministic code, tool call, or LLM/agent) taking exactly one input and producing exactly one output (Topic 1, Topic 11)
**Node Similarity** — a Neo4j Graph Data Science algorithm generating weighted connections to determine entity equality via thresholds (Topic 8)
**Ontology-Guided Extraction** — constraining an LLM's extraction pipeline with a formal schema injected into the prompt, defining allowed entity/relationship types and domain/range constraints (Topic 3, Topic 4, Topic 9)
**Open-World Assumption** — OWL's reasoning stance: missing information is "unknown," not "false" (Topic 3)
**OWL (Web Ontology Language)** — W3C standard defining formal logic, classes, and property restrictions for a domain (Topic 1, Topic 3)
**Perspective-Diverse Verification** — assigning each verifier a distinct analytical lens (correctness, security, reproducibility) to avoid shared blind spots (Topic 13)
**PinSage** — Pinterest's web-scale GCN combining random walks with visual/structural features, processing up to 3 billion nodes (Topic 1, Topic 8, Topic 10)
**Pipeline (streaming)** — pushing each item through multiple stages independently with no inter-stage barrier, as the default alternative to unjustified barriers (Topic 12)
**Property Graph** — a graph model optimized for analytics/traversal, queried via Cypher/Gremlin, storing rich metadata natively in nodes and edges (Topic 1, Topic 2)
**Reducer** — a function annotating a state field to safely merge concurrent parallel writes (e.g. `operator.add`, `add_messages`), preventing the Merge Problem (Topic 12)
**Reification** — RDF 1.2/RDF-star's mechanism for making statements about statements, attaching metadata (confidence, provenance) directly to a triple (Topic 1, Topic 3)
**Schema-on-Read vs. Schema-on-Write** — graph databases favor flexible, dynamically-modifiable schema (schema-on-read) over relational databases' rigid, migration-costly schema-on-write (Topic 2)
**SHACL (Shapes Constraint Language)** — W3C validation standard defining "shapes" data must conform to, under a closed-world assumption (Topic 1, Topic 3)
**SKOS (Simple Knowledge Organization System)** — W3C standard managing taxonomies and controlled vocabularies, distinct from OWL's logical rules (Topic 3)
**Smurfing** — a fraud pattern of fragmenting large deposits into smaller, less suspicious ones across a network, detectable via graph traversal (Topic 8)
**Super-Node** — an entity with exceptionally high connectivity, causing traversal bottlenecks and write-lock contention (Topic 5, Topic 6)
**Temporal CC Forest** — chronological events linked with strictly forward-pointing edges (e.g. `:SAME_CC_AS`), preventing ML "future leakage" (Topic 2, Topic 5, Topic 10)
**Test Gate** — an executed, objective check (compiler, linter, test suite) deciding acceptance instead of a model's subjective self-report (Topic 13)
**Time-Tree Pattern** — hierarchical time partitioning (Year→Month→Day→Event) for fast temporal range scans (Topic 2, Topic 5)
**Traversal-First Thinking** — modeling data natively around the paths and relationships a system needs to walk, instead of optimizing for tabular scans (Topic 1, Topic 2)
**Tree Pattern** — graph design pattern for hierarchies/folder structures with bounded-depth traversal (Topic 2, Topic 5)
**Vertex-Cut Partitioning** — GraphX's partitioning approach letting high-degree vertices span multiple machines to reduce network overhead (Topic 7)
**Weakly Connected Components (WCC)** — algorithm partitioning a graph into disjoint, unreachable subgraphs, enabling "parallelism for free" (Topic 7, Topic 8, Topic 10)
**Zero-Token Coordination** — routing/merging/deduplication logic living entirely in deterministic code rather than LLM calls, costing zero model tokens (Topic 11)
