# Chapter 14: Choosing Names

## Core Idea
Good names are a form of documentation. A precise name reduces the need for comments and lowers cognitive load.

## Key Concepts
- **Precision**: A name should be precise enough to uniquely identify what the variable/method does without being overly long.
- **Consistency**: Use the same name for the same concept everywhere in the codebase.

## Anti-patterns
- **Generic Names**: `result`, `data`, `info`, `manager`. These convey almost no information.
- **Misleading Names**: Names that imply one behavior but the implementation does another.

1. Spend time choosing names. If you can't think of a good name for a module, it might be a sign that the module lacks a clear, cohesive purpose.\n
