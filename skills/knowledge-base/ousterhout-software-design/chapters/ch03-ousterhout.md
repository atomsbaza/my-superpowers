# Chapter 3: Working Code Isn't Enough (Tactical vs. Strategic Programming)

## Core Idea
Prioritizing short-term feature delivery (tactical programming) over long-term system health guarantees a rapid accumulation of technical debt and complexity.

## Frameworks Introduced
- **Strategic Programming**:
  - When to use: Always, except in true throw-away prototyping.
  - How: Accept that writing good design requires an upfront investment (roughly 10-20% extra time). Your goal isn't just working code, but a system whose design makes the *next* feature easier to add.
- **Tactical Tornado**:
  - What it is: A developer who pumps out features rapidly but leaves a wake of complexity and technical debt behind them.

## Anti-patterns
- **Tactical Programming**: "I just need to get this feature working." This mindset justifies hacks and shortcuts that slowly destroy the codebase.

## Key Takeaways
1. The most important goal is a great design, not just working code.
2. The "investment" in design pays off very quickly (often within months).\n
