# Chapter 16: Modifying Existing Code

## Core Idea
When modifying code, do not just make the minimal localized change to fix the bug or add the feature. Invest slightly more to improve the system's design.

## Frameworks Introduced
- **Strategic Modification**:
  - How: When adding a feature, ask: "If this feature had been part of the original design, how would the system be structured?" Then, refactor the system toward that ideal structure before adding the feature.
  - The Boy Scout Rule: Always leave the codebase a little better than you found it.

## Key Takeaways
1. Code rots because of tactical modifications.
2. Refactoring should not be a massive scheduled event; it should be a continuous, small part of every task.\n
