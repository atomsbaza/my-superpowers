# Chapter 17: Consistency

## Core Idea
Consistency reduces cognitive load. If similar things are done in similar ways everywhere in the system, developers can learn a pattern once and apply it everywhere.

## Key Concepts
- **Forms of Consistency**:
  - Naming conventions.
  - Coding style (formatting, indentation).
  - Interfaces (e.g., all I/O classes have a similar `Open`/`Close` lifecycle).
  - Design patterns.

## Key Takeaways
1. "Don't change existing conventions." If you enter a new codebase, adapt to their style, even if you prefer another. Consistency is more important than "correctness" of style.
2. Document your conventions so newcomers can learn them easily.\n
