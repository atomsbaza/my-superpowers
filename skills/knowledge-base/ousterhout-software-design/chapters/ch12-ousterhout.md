# Chapter 12: Why Write Comments? The Four Excuses

## Core Idea
Comments are essential for hiding complexity. Developers avoid writing them using predictable, but flawed, excuses.

## Key Concepts
- **The Four Excuses**:
  1. *"Good code is self-documenting."* (False: code cannot explain *why* a decision was made, or high-level architecture).
  2. *"I don't have time."* (False: writing comments takes a tiny fraction of total dev time, but saves massive time later).
  3. *"Comments get out of date."* (Partially true, but preventable by keeping comments near the code they describe).
  4. *"All the comments I see are worthless."* (True, because people write bad comments. We must learn to write good ones).

## Key Takeaways
1. Code tells you *what* and *how*. Comments tell you *why*.
2. A deep module requires documentation for its interface, because the implementation is intentionally hidden.\n
